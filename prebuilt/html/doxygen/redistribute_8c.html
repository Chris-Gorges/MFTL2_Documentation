Detailed Description

Redistribution: re-partitioning a distributed mesh over the process grid.

Author
Christian Gorges
Date
2026-08-14

Both public entry points run redistribute_core(); MFTLRedistribute() is MFTLRedistributeWithOwners() with the geometric owner rule.

Most of a partition does not move, so kept entities never touch the wire format:

kept -> a PERMUTATION of the pool: records and positions are gathered into scratch in final order and written back. arrivals -> de-duplicated through a global-id table (gt_* in comm_internal.h) and appended. twins -> REPAIRED, not rebuilt: a twin between two kept triangles is an index remap; only half-edges that lost their partner are re-paired.

Why the incremental twin repair is complete. Kept-ness is decided per triangle, so a kept half-edge's twin survives iff the twin's triangle is kept, and then both are remapped consistently. A half-edge whose twin did not survive can only pair with another such half-edge, so the repair set is closed under the twin relation and bucketing it against itself finds every pair a full MFTLRebuildTwins() would. tests/test_redistribution.c re-runs MFTLRebuildTwins() after a redistribution and asserts that nothing changes.

◆ refresh_geometry_before_routing()

void refresh_geometry_before_routing ( MFTL_Object * obj)
static

Recomputes the triangle geometry of a body whose centres the library knows to be out of date, before routing by them.

Called when MFTL_DERIVED_GEOMETRY is clear: no pass over every triangle since the last ghost sync, topology change or rebuild. That catches the inconsistent cases – no pass at all, a pass over the owned triangles only (ghost centres stale), a pass before the ghost sync, a second redistribution without one (arrivals unspecified) – in O(1) per body. It cannot catch owned vertices moved after a full pass: that leaves every holder with the same stale centres, so the partition lags one step but stays consistent.

Local and deterministic: it computes what the caller should have, from the same positions, so it needs no agreement between ranks. Debug asserts if the centres were actually stale, so a test cannot pass by relying on it.

Parameters
objThe mesh; routed by the geometric rule.

Destination analysis: which ranks each OWNED triangle goes to, and what this rank keeps.

Destinations of triangle t: its owner, the owners of its three corners and the owners of its three edge neighbours (the halo rule). This rank is one destination like any other, recorded as keep flags instead of a copy. Ghost triangles are never forwarded. Interior triangles, whose seven candidates all name one rank, take a register-only fast path (an XOR-OR test); otherwise the candidates are collected in first-seen order, which fixes the wire order and hence the arrival slot order.

◆ MFTLRedistributeSetSkipUnchangedBodies()

void MFTLRedistributeSetSkipUnchangedBodies ( bool on)

Allows redistribution to skip bodies nobody saw change (default ON).

A rank's state after a redistribution is a function of (global topology, owner map) only – positions decide the owner map but, once it is fixed, moving a vertex within its cell changes nothing about who holds what. A body is skipped when no rank saw any of its entities change owner and nothing stamped it partition-dirty (MFTLObjectMarkPartitionDirty()): all classification, packing and rebuild work for it is omitted. The verdict is agreed per body with one MFTLEnsembleReduceBodies() call.

The skip is EXACT, slot for slot: because a rebuild is not idempotent (an owned vertex whose incident triangles are all remote is dropped and re-received at the end of the run), a body is rebuilt once more after it stops changing before it may be skipped (partition_settled). parallel_advection_redistribute_list --digest and test_skipping_reproduces_the_full_rebuild compare set and slot-order digests. Anything that rewrites global ids or flags, or creates/destroys entities outside MFTLObjectSetCounts(), must stamp the object dirty.

◆ MFTLRedistribute()

int MFTLRedistribute ( MFTL_Ensemble * ens)

Re-partitions every local object with the geometric owner rule, in one communication round for the whole ensemble.

  1. Analysis. Every entity's owner is recomputed (MFTLGetOwnerProc()); each OWNED triangle is destined for its owner plus the owners of its corners and edge neighbours. Entities this rank keeps are marked, not packed. Ghost triangles are never forwarded (their owner sends the authoritative copy). Bodies nobody saw change are left alone (MFTLRedistributeSetSkipUnchangedBodies()).
  2. Route. One MPI_Allreduce (LOR) decides whether any destination lies outside the 26-neighbourhood; if so the exchange uses comm_cart.
  3. Exchange. Vertices, triangles and one 7-int header per (body, destination) as three payloads of one MFTLExchangeStart(); all bodies share the messages, so the message count is independent of the body count.
  4. Rebuild. Kept entities are compacted in place into the layout [kept owned | new owned | kept ghost | new ghost]; arrivals are de-duplicated by global id; only half-edges that lost their twin are re-paired; out_he_idx and the derived arrays are emitted inline. Bodies that arrived are created, bodies left empty destroyed.
Parameters
ensThe ensemble; every local object is repartitioned in place. Its triangle centres must be current, ghosts included (MFTLEnsembleComputeTriangleGeometry(); a body whose MFTL_DERIVED_GEOMETRY bit is clear is recomputed first, see the file comment; asserted in Debug).
Returns
MFTL_SUCCESS, or MFTL_ERROR on a NULL ensemble.
Collective:
Must be called by every rank of the ensemble's communicator. Ranks holding no bodies must call it too; an ensemble without bodies is a no-op.
Warning
Invalidates every pool index, every MFTL_Object pointer and all cached geometry except vertex positions (see the file comment).
