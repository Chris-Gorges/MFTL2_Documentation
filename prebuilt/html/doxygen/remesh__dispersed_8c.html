Detailed Description

Distributed remeshing for bodies SMALLER than a rank box: move the bodies, not the cut planes.

Author
Christian Gorges
Date
2026-08-17

The same problem from the opposite end

An edge whose endpoints belong to two ranks can be collapsed by neither. remesh_parallel.c moves the cut planes until every entity has been interior somewhere; for a body that fits in a rank box it is simpler to migrate the whole body onto one rank, where no edge is shared. Both are exact; R/h decides which is cheaper: 

         R >> h                              R << h

move the planes the bodies phases about 4 at budget 4 (np = 2..8) 1 migrations one per placement, plus one exactly 2 frozen O(delta/h) of the mesh nothing id cost per-phase holder prefix sums one per-body MAX, total weakness phase count, band precondition load balance at N_bodies < P

Why the ids need almost nothing

After centering exactly ONE rank holds any entity of a body, and ids live in a per-body space (next_*_gid is per object), so that rank's counter is already unique for the body. The operators run untouched, MFTLRemeshRenumberGlobalIds() makes the ids dense on the owner, and the other holders learn the counters by one per-body MAX over the holders (a rank holding nothing contributes zero).

Ordering

Admission is decided BEFORE anything is modified: if a body is too large, the whole ensemble goes to the spanning driver, whose per-phase id scan assumes all holders enter with the same id counters – which a half-remeshed ensemble would violate. The test uses radii already reduced for the strategy decision, so it costs one small reduction.

The box width a body's radius is judged against: the rank box, or the COARSENED box when the fallback is armed and the fine one is too small.

═══════════════════════════════════════════════════════════════════════════ WHY THE YARDSTICK MOVES AND THE ROUTING DOES NOT ═══════════════════════════════════════════════════════════════════════════

r_max > frac * h_min sends the whole ensemble to the spanning driver. Raise the rank count on a fixed domain and h_min shrinks, so a spray of droplets that are ABSOLUTELY tiny becomes RELATIVELY large and is classified SPANNING – for a reason that has nothing to do with the bodies and everything to do with how many ranks were asked for. The spanning driver is the wrong answer there by roughly two migrations against thirty-four.

What the test is actually asking is "can one rank reasonably hold this body", and that question is answered by whatever box the pass is willing to work in. So when parallel_coarsen is armed, the yardstick becomes the coarsened box group[k] * h_k – the same relaxation the spanning driver would apply to itself, capped by the same knob.

── The yardstick moves; the DESTINATIONS do not ──────────────────────────

Nothing here changes where a body is sent. Routing through coarse group representatives would restrict destinations to P/G ranks and undo the load balancer, which needs every rank to be reachable. The coarse box appears ONLY as the size a rank is deemed able to hold, which is a memory statement and not a routing one.

══ THE RELAXATION IS BOUNDED, AND THE BOUND IS NOT GEOMETRIC ══════════════

An unbounded version of this is worse than useless, and it is worth saying exactly how because it is not obvious and it is what the tests caught. The factors clamp at cuts[k], so on a 2x1x1 grid the coarse box is the WHOLE DOMAIN – every body fits, SPANNING becomes unreachable, and a jet spanning the domain gets serialised onto one rank while reporting itself perfectly centred.

The real precondition for relaxing is not about the body at all. Dispersed puts one body on one rank, so it uses min(N_bodies, P) ranks and no more – and the relaxation is worth having exactly when that is still all of them. With fewer bodies than ranks the strategy is already leaving ranks idle, the relaxation buys no parallelism, and all it does is take a large body that the spanning schedule would have shared and give it to one rank. So:

N_bodies >= nproc there are enough bodies to keep the machine busy, and the fine box has stopped being a statement about the bodies and started being one about the rank count G < nproc never merge the entire grid into one box. That is the gather, it is a spanning-path decision, and it has its own parameter with its own memory bound

── It must give the same answer to the chooser and to the driver ─────────

Both call this. If they disagreed, the chooser would elect DISPERSED on a body the driver then rejects, and the pass would pay a wasted measurement and fall back to spanning – correct, slower, and reported only as n_bodies_not_centred.

Is neighbour slot a preferred to slot b at equal usefulness?

══ A TIE-BREAK THAT IS THE SAME ON EVERY RANK STARVES THE SAME RANK ═══════

The obvious tie-break – lowest rank id – is deterministic, total, and wrong here, because it is the SAME ORDERING ON EVERY SENDER. Four overloaded ranks looking at four equally empty neighbours all pick the same one, then the same second one, and the fourth is never chosen by anybody: measured as 1 of 8 ranks left idle on a spread fixture that has thirty-two bodies for eight ranks. Nothing is wrong with the mesh and the imbalance still reports 1.25 – this is a tie-break, not a correctness rule – but a rank was left with nothing to do for no reason.

The fix has to make different senders prefer different targets, and the MEANING is already available: the cell OFFSET of a neighbour is relative to the rank doing the looking, so a nearer destination is both a different choice on every rank and a genuinely cheaper migration – redistribution's stencil is a box, and a body sent one cell stays inside more senders' halos than one sent across a corner. Manhattan distance first, rank id second so the order stays total.

Remeshes a distributed ensemble by moving the BODIES (DISPERSED).

For bodies smaller than a rank box (emulsions, sprays, bubbly flows). Every entity of a body is migrated to one rank – its centroid's owner, adjusted by the load balancer (dispersed_balance_slack) – so the body arrives whole with no ghosts and MFTLRemeshObject() runs on it unchanged. No freezing, no phases, exactly two migrations (out, and the closing MFTLRedistribute()); ids need only a per-body MAX of the id counters over the holders.

Admission is tested BEFORE anything moves, on the body radius (a one-destination migration would make any body local, even one spanning the domain, and serialise it onto one rank): if any body is too large, the whole ensemble goes to MFTLRemeshEnsembleParallel() untouched (MFTL_RemeshStats::n_bodies_not_centred). Pre- and postconditions are those of MFTLRemeshEnsembleParallel() without \(h > 4\delta\).
