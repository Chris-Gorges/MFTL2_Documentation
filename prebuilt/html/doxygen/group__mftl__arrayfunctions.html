Detailed Description

Stable LSD radix sort over 8-bit digits, for keys and key/value pairs.

The algorithm

A least-significant-digit radix sort makes \(\lceil b/r \rceil\) stable counting-sort passes over \(n\) keys of \(b\) bits, \(r\) bits at a time, for a total cost of

\[ O\!\left(\frac{b}{r}\,(n + 2^{r})\right) \]

With \(r = 8\) the histogram of one pass is \(2^8\) counters, i.e. 1 KiB, and all \(b/r\) histograms together are 4 KiB (32-bit keys) or 8 KiB (64-bit). Both fit in L1D, which is what makes the implementation's central trick worthwhile: every digit of every key is counted in a single streaming pass over the data, so the keys are read once for counting and once per scatter pass rather than \(2b/r\) times.

Two refinements matter in practice:

  • Constant-digit passes are skipped. If a digit position takes the same value in all \(n\) keys, its histogram has one non-zero bucket and the pass is the identity. Mesh global IDs are dense in \([0,n)\), so the top two bytes of a 32-bit ID are usually constant and half the passes vanish.
  • Signed 32-bit ordering is free. The most significant pass processes the sign byte; running its prefix sum starting from bucket 128 and wrapping to bucket 0 places negative keys first without ever flipping a bit.

Below INSERTION_CUTOFF elements the fixed costs (histogram clear, the 256-entry prefix sums, the temp allocation) outweigh the \(O(n^2/4)\) moves of an array that never leaves L1, and a stable insertion sort takes over.
