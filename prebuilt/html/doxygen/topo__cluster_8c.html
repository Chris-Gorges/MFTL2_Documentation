Detailed Description

The reconstruction lattice, the clusters, and each rank's window.

Author
Christian Gorges
Date
2026-09-25

ONE LATTICE, ALIGNED TO EVERYTHING

The lattice divides every axis into cuts[k] * m cells. Two alignments follow, and every other file relies on them:

A NODE PLANE ON EVERY WALL. A surface meeting a wall – the rim of an open interface – is cut by marching cubes exactly in the wall plane, so the reconstructed rim lies ON the wall rather than a fraction of a cell away.

A NODE PLANE ON EVERY CUT PLANE. Every lattice cell lies inside exactly one rank box, so "who owns this cell" is integer arithmetic and every triangle marching cubes produces has exactly one owner, whatever rank computed it.

A WINDOW, NOT A GRID

No rank stores the lattice. It stores a WINDOW per cluster: its own box, plus a pad wide enough that every owned triangle's rasterisation footprint fits, intersected with the cluster's extent. That is the original design's "component grid" per interacting cluster, cut into per-rank pieces – memory follows the part of the cluster near this rank, never the domain.

void MFTLTopologyLattice ( const MFTL_Domain * domain,
double dx,
double spacing[3],
int cells[3] )

The reconstruction lattice for a domain and a target spacing.

Axis k has cells[k] = cuts[k] * max(1, round(L_k / (cuts[k] * dx))) cells of spacing[k] = L_k / cells[k], anchored at global_min[k]. Two properties follow and the whole reconstruction rests on them: a node plane lies on every domain wall, so a surface meeting a wall is cut exactly there, and a node plane lies on every rank's cut plane, so every lattice cell belongs to exactly one rank.

Parameters
domainThe domain.
dxTarget spacing, > 0.
[out]spacingActual spacing per axis.
[out]cellsCells per axis.
Rank-local:
Performs no MPI. Each rank operates on its own partition. Pure function of the domain.
