Detailed Description

Helpers shared by the remeshing translation units. Not a public header.

Author
Christian Gorges
Date
2026-08-15

Almost everything here is static inline and exists to make the operators in remesh_ops.c read as topology rather than as index arithmetic. The two that carry real weight are tri_write() – which is the only place the "he[3t+k].vertex_idx is the TARGET of corner k" convention is spelled out – and remesh_new_triangle(), which is the only place a half-edge triple comes into existence.

The exceptions are at the bottom: the freeze gate the parallel driver imposes on the sweeps, and MFTLRemeshIterate(), the one function with external linkage that both drivers call. It is here rather than in include/ because it is not part of the library's API – but it still carries the MFTL prefix, because nothing without one may be exported.

◆ MFTL_REMESH_RING_MAX

#define MFTL_REMESH_RING_MAX   64

One-ring scratch buffer size.

Larger than MFTL_MAX_VALENCE (32) on purpose. The library's walkers stop at MFTL_MAX_VALENCE and a boundary vertex reports one MORE neighbour than it has triangles, so a buffer of exactly MFTL_MAX_VALENCE cannot distinguish "valence 32" from "the walk was truncated". With headroom, count == MFTL_MAX_VALENCE is an honest answer and truncation is detectable – and every operator below REFUSES rather than proceeds on a truncated ring.

◆ MFTL_REMESH_DEGENERATE_SIN2

#define MFTL_REMESH_DEGENERATE_SIN2   MFTL_VERYVERYSMALL

Squared sine of a corner angle at or below which a fold test treats the triangle as degenerate.

DIMENSIONLESS, so the verdict is the same at every length scale. An absolute threshold on the squared area vector (dimension L^4, compared with 1e-15) refused every collapse and flip for edges below about 1.8e-4 – a millimetre droplet in SI units – so the mesh could only be refined (test_remeshing_is_independent_of_the_length_unit). 1e-15 as a ratio is the floor below which the cross product is rounding noise.

Writes triangle t as the CCW vertex triple (v0, v1, v2).

Half-edge 3t+k runs from v[k] to v[(k+1)%3] and stores only its TARGET, so the triple lands as (v1, v2, v0). This is the single point at which that rotation is expressed; MFTLGetTriangleVertices() and tris.verts read it back out and the three must agree, or triangles come out silently rotated.

Deliberately does NOT touch twins, flags or global ids: a rewrite has to place each logical edge's flags in its NEW slot, and only the caller knows which slot that is.

Parameters
objThe mesh.
tTriangle index.
v0First corner.
v1Second corner.
v2Third corner. The three must be distinct (asserted in Debug).

Would splitting or flipping h modify something this rank does not own?

Both operators rewrite the two triangles incident to the edge and nothing else – a split additionally APPENDS, and an appended entity is by definition not replicated anywhere. So the gate is the two incident triangles, and their corners come along for free: a triangle is frozen whenever any of its corners is a ghost, so an unfrozen triangle's corners are all owned.

◆ freeze_blocks_collapse()

bool freeze_blocks_collapse ( const MFTL_Object * obj,
int h )
inlinestatic

Would collapsing h modify something this rank does not own?

The modified set is larger than it looks: the origin vertex dies, the target MOVES, and every triangle in the origin's fan has that corner rewritten. Two flag tests cover all of it, and the reason is worth stating because it is what makes a fan walk unnecessary here:

a vertex is unfrozen => every triangle incident to it is unfrozen

which holds by construction – MFTLRemeshMarkFrozen freezes the corners of every triangle it freezes. So "both endpoints unfrozen" already asserts that the whole fan is this rank's to rewrite, and it additionally guarantees that the fan is locally COMPLETE, because an unfrozen vertex is owned and the redistribution halo is vertex-complete. The link condition, the wing valences and the fold-over test can therefore all be evaluated exactly.

Parameters
objThe mesh.
hHalf-edge index; its ORIGIN is the vertex that would be retired.
Returns
true if the collapse must be refused.
