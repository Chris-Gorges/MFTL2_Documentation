Detailed Description

Linear BVH over triangle primitives, and exact triangle-triangle contact.

Linear BVH construction

An LBVH (Lauterbach et al. 2009): assign each primitive a 63-bit Morton code from its centroid, sort, then build the hierarchy by radix splitting — an internal node covering a sorted range \([i, j]\) splits where the highest differing key bit changes, found by a binary search on the common prefix length \(\delta(a,b) = \mathrm{clz}(Z_a \oplus Z_b)\). Equal codes are made unique by appending the index (Karras 2012), so the whole tree is a function of the sorted key array and needs no partitioning pass.

Bounding boxes are then fitted bottom-up. When only the geometry moved, the refit alone is valid and the sort and split are skipped — that is MFTL_RefitLBVH().

Periodicity is two problems, and they need two different fixes

  • Within an object, a triangle straddling a seam has wrapped vertices, so a centroid built from raw coordinates lands in the middle of the domain and its AABB spans the box. Fixed by gathering the current corners and applying minimum-image edges to build every primitive.
  • Between objects, two bodies on opposite faces are neighbours and no per-triangle arithmetic can see it. Fixed by traversing the pair once per periodic IMAGE (up to 27, each rejected by one root-AABB test).

The contact envelope

\[ \tau = \max\big(\texttt{proximity\_floor},\; \texttt{proximity\_factor} \cdot R\big) \]

where \(R\) is half the longest side of the root box, not half its diagonal, so \(R\) equals the radius for a sphere and the factor means what it says. \(R\) is measured over one rank's partition, so the distributed pipeline overwrites it with the body's global radius from one reduction — otherwise splitting a droplet over eight ranks would change the separation at which contact is detected.

The narrow phase

Guigue & Devillers' triangle-triangle overlap test, which decides the question with a sequence of orientation predicates

\[ \mathrm{orient3d}(\mathbf{a},\mathbf{b},\mathbf{c},\mathbf{d}) = \operatorname{sign} \det \begin{pmatrix} a_x - d_x & a_y - d_y & a_z - d_z \\ b_x - d_x & b_y - d_y & b_z - d_z \\ c_x - d_x & c_y - d_y & c_z - d_z \end{pmatrix} \]

MFTL_Orient3D() is Shewchuk-adaptive: it evaluates the determinant in floating point together with a running error bound, and only escalates to exact expansion arithmetic when the bound does not separate the result from zero.

Warning
src/bvh/bvh_predicates.c must be compiled with -ffp-contract=off. An FMA contracts \(x - ab\) into one rounding, Two_Product's residue comes out zero, and every exactness guarantee evaporates while the numbers still look plausible.
Note
A distributed contact is reported by the rank that owns the A-side primitive, and only that rank. So a BVH is built over owned triangles only, only object B's triangles travel, and the traversal skips any leaf pair whose A side is remote.
