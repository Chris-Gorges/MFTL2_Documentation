Detailed Description

Every MFTL struct, defined in exactly one place.

The one idea

A mesh is described by two things that want opposite memory layouts, and each is stored in the layout it wants:

  • Topology and identity → AoS. MFTL_Vertex (16 B), MFTL_Triangle (12 B), MFTL_HalfEdge (16 B). A remesher edits one entity at a time and touches most of its record when it does.
  • Geometry → SoA. Positions, normals, areas and centroids. These are read and written by kernels that touch one component of every entity, every timestep.

Both live in one allocation per entity class. MFTL_VertexPool and MFTL_TrianglePool each hold a single block cut into cache-line-aligned sub-arrays by MFTLLayoutAdd(), and each has exactly one capacity.

Three invariants every module may assume

  1. Half-edges are triangle-indexed. Half-edge \(3t+k\) belongs to triangle \(t\), and \(\mathrm{next}(3t+k) = 3t + (k+1) \bmod 3\). he_idx, next_idx and triangle_idx are therefore not stored — they are arithmetic (MFTLTriFirstHe(), MFTLHeTriIdx(), MFTLHeNextIdx(), MFTLHePrevIdx()).
  2. Ownership is a prefix. Entities \([0, n_\mathrm{local})\) are owned by this rank; \([n_\mathrm{local}, n)\) are ghosts. There is no is_ghost field.
  3. Positions live in the SoA and only there. verts.pos[3*v+k] is authoritative. The Morton ordering is applied to the pool, not stored as a permutation.
