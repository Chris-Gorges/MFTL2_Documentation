Detailed Description

The three topological operators and their approval predicates.

Author
Christian Gorges
Date
2026-08-15

THE SHAPE EVERY OPERATOR HAS, AND WHY

  1. READ the patch into locals: vertex indices, rim twin indices, rim flags.
  2. ALLOCATE whatever new entities are needed.
  3. WRITE the triangles, place the flags, re-link the rim.
  4. REPAIR the affected vertices' out_he_idx.

Step 1 must complete before step 2 because allocation can move both pool blocks, and step 3 must not begin before step 2 for the same reason. That is the one rule the AoS-in-a-pool layout imposes on a remesher, and it is cheap: a patch is a dozen integers.

Step 3 is where implicit indexing shows up. When triangle t is rewritten, the logical edge that occupied slot 1 may end up in slot 2, so the rim FLAGS have to be carried explicitly – a half-edge record does not move with its edge, only its contents do. MFTL_FLAG_FEATURE and MFTL_FLAG_BOUNDARY are both properties of the EDGE; losing one during a split is invisible until a ridge develops a gap several timesteps later.

WHY THE PREDICATES ARE THIS LONG

Every clause in MFTLCollapseApproved corresponds to a mesh that is still a valid data structure and no longer a valid surface. None of them announce themselves: a violated link condition produces a non-manifold vertex whose one-ring walk silently visits half the fan, and a fold-over produces an inverted triangle that the feature detector then reads as a sharp edge and the smoother locks in place forever. The predicates are the whole correctness argument of the module; the execution functions assume it has been made.

◆ MFTLCollapseApproved()

bool MFTLCollapseApproved ( const MFTL_Object * obj,
int h,
const MFTL_RemeshParameters * params,
int * reject_reason )

Is collapsing half-edge h (its origin into its target) legal and wanted?

Wanted: shorter than min_edge_length. Each clause prevents a result that is a valid data structure but not a valid surface, and none of them fails loudly:

  • Features: a corner is never retired; a feature (boundary) vertex may only collapse into a feature (boundary) vertex; two feature (boundary) vertices joined by a non-feature (interior) edge may not collapse – that edge is a chord, and collapsing it pinches the curve.
  • Link condition: the endpoints share exactly two neighbours (one at a boundary edge); otherwise two sheets are welded into a non-manifold vertex.
  • Valence: the merged vertex has valence in [3, MFTL_MAX_VALENCE], and each wing vertex has at least 4 neighbours (a tetrahedron passes the link condition and would dissolve).
  • Stretch: no edge of the merged vertex exceeds max_edge_length, or split and collapse oscillate.
  • Fold-over: no surviving triangle's normal turns by more than max_normal_deviation_cos or becomes degenerate (the test is relative to the triangle's own edges, so it is independent of the length unit).

Truncated one-ring walks (valence beyond the scratch size) are refused.

Parameters
objThe mesh.
hHalf-edge index; its ORIGIN would be retired.
paramsSupplies the length band, the fold-over threshold and the feature settings.
[out]reject_reasonMay be MFTL_NULL. Receives a MFTL_REMESH_REJECT_* code.
Returns
true if the collapse is legal and wanted.

void glue_rim ( MFTL_Object * obj,
int x,
int y )
static

Re-links the two rim half-edges of a removed triangle to each other.

Removing a triangle merges two of its edges into one, so the neighbours across those edges become directly adjacent. Either side may be absent, in which case the survivor becomes a mesh boundary half-edge and is flagged as one – the flag is what tells a later pass that this is the edge of the SURFACE rather than of the partition, and it cannot be re-derived after the fact.

The feature bit is OR-ed rather than picked, so a ridge that ran through one of the two edges still runs through the merged one.

Parameters
objThe mesh.
xRim half-edge just written into a new slot.
yIts partner outside the patch, or MFTL_ERROR.

◆ MFTLFlipApproved()

bool MFTLFlipApproved ( const MFTL_Object * obj,
int h,
const MFTL_RemeshParameters * params,
int * reject_reason )

Would flipping half-edge h strictly lower the squared valence deviation of the four quad vertices?

\[ E = \sum_{v \in \{a,b,c,d\}} \big(\deg(v) - \deg^{*}(v)\big)^{2}, \qquad \deg^{*} = \begin{cases} 6 & \text{interior} \\ 4 & \text{boundary} \end{cases} \]

( \(\deg\) counts neighbours). Only a STRICT decrease is accepted, or two flips could alternate forever. Refused for boundary and feature edges, when an endpoint has three neighbours or fewer, when the opposite vertices are already adjacent (a duplicate edge), when a valence would exceed MFTL_MAX_VALENCE, and when either new triangle would turn past max_normal_deviation_cos against the quad's normal (a non-convex quad).

Parameters
objThe mesh.
hHalf-edge index.
paramsSupplies max_normal_deviation_cos.
[out]reject_reasonMay be MFTL_NULL. MFTL_REMESH_REJECT_FOLD only when the valence criterion wanted the flip and the geometry refused it.
Returns
true if the flip strictly lowers \(E\) and is geometrically legal.
