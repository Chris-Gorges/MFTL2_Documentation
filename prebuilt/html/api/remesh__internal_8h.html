    Detailed Description¶

    Author:

    Christian Gorges

    Date:

    2026-08-15

    Almost everything here is static inline and exists to make the operators in remesh_ops.c read as topology rather than as index arithmetic. The two that carry real weight are tri_write() which is the only place the "he[3t+k].vertex_idx is the TARGET of corner k" convention is spelled out and remesh_new_triangle(), which is the only place a half-edge triple comes into existence.

    The exceptions are at the bottom: the freeze gate the parallel driver imposes on the sweeps, and MFTLRemeshIterate(), the one function with external linkage that both drivers call. It is here rather than in include/ because it is not part of the library's API but it still carries the MFTL prefix, because nothing without one may be exported.

    Public Static Functions Documentation¶

    function area_vector_cos¶

    cos of the angle between two area vectors, 0 if either is zero. 

    static inline double area_vector_cos (
    const double a,
    const double b
)

    Returning 0 rather than 1 for a degenerate input is what makes this usable as a rejection test: an operation that produces a zero-area triangle should fail the same threshold an inverting one fails, not pass it by accident. WHAT counts as degenerate is decided where the vector is built, relative to its own edges (fold_area_vector()); here the test is against zero, which has no length scale.

    Parameters:

    • a First area vector.
    • b Second area vector.

    Returns:

    \(\cos\theta\) between them, or 0 if either is zero.

    function fold_area_vector¶

    \(\vect{e}_1 \times \vect{e}_2\) , or the zero vector when the triangle the two edges span is degenerate. 

    static inline void fold_area_vector (
    const double e1,
    const double e2,
    double out
)

    The zero vector is the "not computable" sentinel area_vector_cos() rejects, so a degenerate triangle fails a fold test exactly as an inverted one does.

    Parameters:

    • e1 First edge vector.
    • e2 Second edge vector, from the same corner.
    • out The cross product, or zero.

    function freeze_blocks_collapse¶

    Would collapsing h modify something this rank does not own? 

    static inline bool freeze_blocks_collapse (
    const MFTL_Object * obj,
    int h
)

    The modified set is larger than it looks: the origin vertex dies, the target MOVES, and every triangle in the origin's fan has that corner rewritten. Two flag tests cover all of it, and the reason is worth stating because it is what makes a fan walk unnecessary here:

    a vertex is unfrozen => every triangle incident to it is unfrozen

    which holds by construction MFTLRemeshMarkFrozen freezes the corners of every triangle it freezes. So "both endpoints unfrozen" already asserts that the whole fan is this rank's to rewrite, and it additionally guarantees that the fan is locally COMPLETE, because an unfrozen vertex is owned and the redistribution halo is vertex-complete. The link condition, the wing valences and the fold-over test can therefore all be evaluated exactly.

    Parameters:

    • obj The mesh.
    • h Half-edge index; its ORIGIN is the vertex that would be retired.

    Returns:

    true if the collapse must be refused.

    function freeze_blocks_pair¶

    Would splitting or flipping h modify something this rank does not own? 

    static inline bool freeze_blocks_pair (
    const MFTL_Object * obj,
    int h
)

    Both operators rewrite the two triangles incident to the edge and nothing else a split additionally APPENDS, and an appended entity is by definition not replicated anywhere. So the gate is the two incident triangles, and their corners come along for free: a triangle is frozen whenever any of its corners is a ghost, so an unfrozen triangle's corners are all owned.

    Parameters:

    • obj The mesh.
    • h Half-edge index.

    Returns:

    true if the operation must be refused. Always false on a ghost-free object, which is what makes the gated sweeps bit-identical to the serial remesher.

    function remesh_new_triangle¶

    Appends a triangle AND its three half-edges. 

    static inline int remesh_new_triangle (
    MFTL_Object * obj
)

    There is no separate half-edge allocator, and there cannot be one: the three half-edges of triangle t are 3t..3t+2 in the same block, so they come into existence exactly when it does. Their global ids are 3 * (triangle gid) + k, which is the invariant redistribution relies on to avoid transmitting them.

    Parameters:

    • obj The mesh. May reallocate both pool blocks.

    Returns:

    The new triangle's pool index. Its half-edges are at 3t, 3t+1, 3t+2 with cleared twins and flags.

    function remesh_new_vertex¶

    Appends a vertex at pos with a fresh global id. 

    static inline int remesh_new_vertex (
    MFTL_Object * obj,
    const double pos
)

    Ownership is an array prefix and an append lands at the END of the pool. On a ghost-free object those coincide and n_local grows with the pool. On a partitioned object the new vertex stays past the ghosts, recognisable by owner_proc, until MFTLRemeshCompactObject() restores the prefix; nothing in between may decide ownership by index, which is why the parallel gate is MFTL_FLAG_FROZEN. A new entity is owned, unreplicated and unfrozen.

    Parameters:

    • obj The mesh. May reallocate both pool blocks.
    • pos Position of the new vertex.

    Returns:

    Its pool index. out_he_idx is MFTL_ERROR; the caller links it.

    function remesh_stats_accumulate¶

    Adds one object's per-pass operation counts into a running total. 

    static inline void remesh_stats_accumulate (
    MFTL_RemeshStats * dst,
    const MFTL_RemeshStats * src
)

    The one place the per-object counters of MFTL_RemeshStats are summed, used by all three drivers. The counters are sums; iterations is the maximum, because the objects of one pass iterate side by side rather than one after another. Fields that describe the PASS rather than an object (phases, migrations, the profile) are the driver's own and are not touched.

    Parameters:

    • dst The running total.
    • src One object's statistics.

    function tri_area_vector_substituted¶

    Twice the area vector of triangle t , optionally with one or two of its corners moved tosub_pos . 

    static inline void tri_area_vector_substituted (
    const MFTL_Object * obj,
    int t,
    int sub_a,
    int sub_b,
    const double sub_pos,
    double out
)

    Parameters:

    • obj The mesh.
    • t Triangle index.
    • sub_a Vertex index to substitute, or MFTL_ERROR.
    • sub_b Second vertex index to substitute, or MFTL_ERROR.
    • sub_pos Position both substituted corners take.
    • out \(\vect{e}_1 \times \vect{e}_2\), un-normalised, so its magnitude is twice the area or zero when the triangle is degenerate (fold_area_vector()).

    The substitution is what makes a fold-over test possible without editing the mesh first: an operator asks "what would this triangle's normal be afterwards" and compares. Passing MFTL_ERROR for both sub_a and sub_b gives the current normal, from the same code path, so the comparison cannot be skewed by two slightly different formulas.

    Un-normalised on purpose: only its direction and whether it is zero are read.

    function tri_write¶

    Writes triangle t as the CCW vertex triple (v0, v1, v2). 

    static inline void tri_write (
    MFTL_Object * obj,
    int t,
    int v0,
    int v1,
    int v2
)

    Half-edge 3t+k runs from v[k] to v[(k+1)%3] and stores only its TARGET, so the triple lands as (v1, v2, v0). This is the single point at which that rotation is expressed; MFTLGetTriangleVertices() and tris.verts read it back out and the three must agree, or triangles come out silently rotated.

    Deliberately does NOT touch twins, flags or global ids: a rewrite has to place each logical edge's flags in its NEW slot, and only the caller knows which slot that is.

    Parameters:

    • obj The mesh.
    • t Triangle index.
    • v0 First corner.
    • v1 Second corner.
    • v2 Third corner. The three must be distinct (asserted in Debug).

    Macro Definition Documentation¶

    define MFTL_REMESH_DEGENERATE_SIN2¶

    Squared sine of a corner angle at or below which a fold test treats the triangle as degenerate. 

    #define MFTL_REMESH_DEGENERATE_SIN2 `MFTL_VERYVERYSMALL`

    DIMENSIONLESS, so the verdict is the same at every length scale. An absolute threshold on the squared area vector (dimension L^4, compared with 1e-15) refused every collapse and flip for edges below about 1.8e-4 a millimetre droplet in SI units so the mesh could only be refined (test_remeshing_is_independent_of_the_length_unit). 1e-15 as a ratio is the floor below which the cross product is rounding noise.

    define MFTL_REMESH_RING_MAX¶

    One-ring scratch buffer size. 

    #define MFTL_REMESH_RING_MAX `64`

    Larger than MFTL_MAX_VALENCE (32) on purpose. The library's walkers stop at MFTL_MAX_VALENCE and a boundary vertex reports one MORE neighbour than it has triangles, so a buffer of exactly MFTL_MAX_VALENCE cannot distinguish "valence 32" from "the walk was truncated". With headroom, count == MFTL_MAX_VALENCE is an honest answer and truncation is detectable and every operator below REFUSES rather than proceeds on a truncated ring.
