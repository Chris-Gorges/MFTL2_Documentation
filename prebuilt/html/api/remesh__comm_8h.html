    function MFTLRemeshAgreeParams¶

    Refuses, on EVERY rank, a parameter block that is invalid on any rank or not identical on all of them. 

    int MFTLRemeshAgreeParams (
    const MFTL_Domain * domain,
    const MFTL_RemeshParameters * params,
    const char * caller
)

    Nothing in a distributed pass communicates the parameters: every rank is assumed to hold the same block. Some fields decide the sequence of collectives (parallel_strategy, parallel_phase_budget, the coarsening controls), the rest decide what happens to shared entities. Two realistic violations, neither with a symptom of its own:

    • A band that is invalid on some ranks only. The usual cause is MFTLMeanEdgeLength() (LOCAL) on a distributed mesh: 0 on a rank holding no triangle of the body. A per-rank refusal returns on that rank and leaves the others in the next collective, which is a hang in Release.
    • Blocks that differ between ranks. Different collective sequences hang; different decisions on shared entities give an inconsistent mesh.

    One MPI_Allreduce(MIN) over every field, every negated field and the local band verdict gives each rank the extremes of every field and the worst verdict, so all ranks reach the same answer; a refusal is useful only if it is unanimous. The band is valid when \(0 \le \ell_{\min} \le \ell_{\max}\) and \(\ell_{\max} > 0\) (NaN fails). Fields must agree bitwise. Rank 0 prints the reason on stderr.

    Parameters:

    • domain The MPI/physical world.
    • params This rank's parameter block.
    • caller Name of the public entry point, for the diagnostic.

    Returns:

    MFTL_SUCCESS on every rank, or MFTL_ERROR on every rank.

    ** **

    Must be called by every rank of the ensemble's communicator. One Allreduce of 49 doubles; at nproc == 1 only the band test.

    function MFTLRemeshAgreeProfile¶

    Replaces the six wall-clock fields of st , and up to two further values, by their maxima over all ranks in ONE MPI_Allreduce. 

    void MFTLRemeshAgreeProfile (
    const MFTL_Domain * domain,
    MFTL_RemeshStats * st,
    double * extra,
    int n_extra
)

    Both distributed drivers publish their profile this way at the end of a pass, and the spanning driver appends its band measurement to the same message. The fields are gathered into a local array rather than reduced through &st->t_total: that spelling would silently depend on the six fields staying adjacent and in this order, and a member added between them is exactly the kind of edit nobody re-reads a reduction for.

    UNCONDITIONAL in the drivers, even when the caller passed no stats struct: the collective must be entered by every rank.

    Parameters:

    • domain The MPI/physical world.
    • st t_total, t_migrate, t_geometry, t_freeze, t_sweep and t_reduce are replaced by their maxima.
    • extra [n_extra] further values, replaced likewise. May be MFTL_NULL when n_extra is 0.
    • n_extra 0, 1 or 2.

    ** **

    Must be called by every rank of the ensemble's communicator.

    function MFTLRemeshMigrateShifted¶

    Redistributes the ensemble under cut planes offset by shift . 

    int MFTLRemeshMigrateShifted (
    MFTL_RemeshMigrator * m,
    MFTL_Ensemble * ens,
    const int group,
    const double shift,
    MFTL_RemeshMigrationReport * report
)

    Routes vertices by position and triangles by their cached CENTRE, i.e. the same two arrays and the same rule as the production path, evaluated against moved planes. Ghosts are routed too, and must be: a rank routes its ghosts in order to work out which of its own triangles the ghost's owner is about to need, so the halo would otherwise come back with holes.

    Preconditions are the redistribution's own current derived arrays, and centres refreshed over the FULL triangle count including ghosts.

    A placement that every entity already satisfies is SKIPPED see the body for why that is sound and why the test has to be global. Phase 0 of the schedule is exactly that case.

    Parameters:

    • m Migrator handle, reused across calls.
    • ens The ensemble.
    • group Per-axis coarsening factors.
    • shift Per-axis cut-plane offset for this phase.
    • report Optional. See MFTL_RemeshMigrationReport.

    Returns:

    MFTL_SUCCESS, or MFTL_ERROR if the redistribution failed.

    function MFTLRemeshMigrateToRanks¶

    Redistributes the ensemble so that local body o lands wholly ondest[o] . 

    int MFTLRemeshMigrateToRanks (
    MFTL_RemeshMigrator * m,
    MFTL_Ensemble * ens,
    const int * dest,
    MFTL_RemeshMigrationReport * report
)

    The object-centering migration of the dispersed strategy: every entity of a body owned and ghost, vertex and triangle is given the same destination, so the body arrives complete on one rank with no ghosts and the untouched serial kernel can run on all of it.

    dest is indexed by LOCAL SLOT, but every HOLDER of a body must still have arrived at the same destination for it MFTL_OwnerMap is undefined, not merely slow, when two ranks name different destinations for one entity. Both of the dispersed driver's paths satisfy that: the unbalanced one applies MFTLGetOwnerProc() to a centroid every holder received identically to the bit from MFTLEnsembleReduceBodies(), and the balanced one decides each body on ONE rank and delivers the verdict to every holder one hop along comm_graph. It is a 26-neighbour exchange exactly when each body fits inside a rank box; when it does not, redistribution notices by itself and falls back to the global communicator, so the failure mode is a slower message pattern and not a wrong answer.

    Parameters:

    • m Migrator handle, reused across calls.
    • ens The ensemble.
    • dest [ens->n_local_objects] destination rank per LOCAL SLOT.
    • report Optional. See MFTL_RemeshMigrationReport.

    Returns:

    MFTL_SUCCESS, or MFTL_ERROR if the redistribution failed.

    ** **

    Must be called by every rank of the ensemble's communicator.

    function MFTLRemeshSyncGhostIds¶

    Tells every ghost vertex the NEW global id its owner has just given it. 

    int MFTLRemeshSyncGhostIds (
    MFTL_Ensemble * ens,
    const int * vertex_gid_base
)

    Parallel remeshing makes the global ids sparse splits hand out ids, collapses retire them and has to re-densify them, but a rank may only renumber what it owns. This closes the gap for the ghosts.

    ── Why a renumbering cannot simply be followed by a redistribution ────────

    Because redistribution KEEPS ghost vertices. A ghost is retained as a corner of a kept owned triangle, and arrivals are de-duplicated against the kept set BY GLOBAL ID. A kept ghost still carrying its pre-renumbering id therefore fails to match the authoritative copy its owner now sends, both survive, and the twin rebuild which pairs by vertex SLOT tears the surface along the partition boundary. Ghost TRIANGLES have no such problem: they are dropped and re-received every time, which is why only the vertices need this.

    ── Why it is here and not a third field of MFTLUpdateGhostPositions ───────

    It asks the same question of the same set, so sharing that schedule was tempting and was in fact tried. The cost landed in the wrong place: the shared function acquired a payload discriminator that every per-timestep position sync then evaluated once per ghost vertex, to serve a call made once per remesh. Written separately it is also strictly cheaper on the wire 4 bytes per ghost instead of the 32-byte MFTL_GhostUpdatePayload, and no registered MPI datatype at all.

    Parameters:

    • ens The ensemble.
    • vertex_gid_base [ens->n_local_objects] first new vertex id this rank was allotted per body, or MFTL_NULL when the ids did not move.

    Returns:

    MFTL_SUCCESS, or MFTL_ERROR if the exchange failed.

    function MFTLRemeshCapGroups¶

    Shrinks group until it merges at mostcap ranks per group. 

    static inline void MFTLRemeshCapGroups (
    int group,
    int cap
)

    Shared rather than duplicated because BOTH paths that coarsen have to apply the same cap: the spanning driver caps the factors it partitions by, and the dispersed strategy caps the factors it uses as a yardstick for "is a body small enough for one rank". Two copies of this loop would eventually differ, and the symptom would be the chooser electing DISPERSED on a body the driver then rejects one wasted migration and a fall back to the spanning path, reported only as n_bodies_not_centred.

    The largest factor is shrunk first, which keeps the merged boxes as close to cubic as the cap allows. A cap below 1 is ignored; cap <= 1 means no cap.

    Parameters:

    • group [3] per-axis factors, each >= 1.
    • cap Maximum group[0]*group[1]*group[2]. <= 1 is a no-op.

    ** **

    Performs no MPI. Each rank operates on its own partition. Pure arithmetic; every rank must call it with the same inputs.

    function MFTLRemeshCoarseOwnerProc¶

    MFTLRemeshOwnerProc() on a decomposition COARSENED bygroup per axis. 

    static inline int MFTLRemeshCoarseOwnerProc (
    const MFTL_Domain * domain,
    const int group,
    const double shift,
    const double pos
)

    The shift schedule needs \(h > 4\delta\); when more ranks shrink h below that, bands along the cut planes are silently never remeshed. A coarser decomposition needs no second communicator: redistribution accepts any destination per entity (MFTL_OwnerMap), so coarsening is just a different owner function fine cell, integer-divided by the group size, mapped to a representative fine cell's rank. Every rank still enters every collective; non-representatives receive nothing. The freeze rule (index >= n_local) and the covering argument transfer with \(H_k = g_k h_k\), and the closing MFTLRedistribute() restores the fine partition.

    Cost: \(1/(g_0g_1g_2)\) of the ranks do all the sweeping, and destinations leave the 26-neighbourhood, so redistribution and MFTLRemeshSyncGhostIds() take their global paths. Per-axis factors keep the loss to the axes that need it.

    Parameters:

    • domain The MPI/physical world.
    • group Per-axis coarsening factors, each >= 1; {1,1,1} is bit-for-bit MFTLRemeshOwnerProc().
    • shift Per-axis cut-plane offset.
    • pos A position, already wrapped into the domain.

    Returns:

    The rank owning pos under the coarsened, shifted decomposition; all ranks of a group map to the same one.

    function MFTLRemeshFineCell¶

    The rank owning pos when every cut plane of axis k sits atglobal_min[k] + shift[k] + j*h_k . 

    static inline int MFTLRemeshFineCell (
    const MFTL_Domain * domain,
    int k,
    const double shift,
    const double pos
)

    MFTLGetOwnerProc with the planes moved, and the shift is exactly what forces the extra branch. Without it the argument of the truncation is non-negative for any wrapped position, so (int) IS floor and clamping is the same as wrapping. With a shift of up to h/2 the argument reaches -0.5, where (int) truncates TOWARDS ZERO and would report cell 0 for a point belonging to cell cuts-1 on the far side of the seam. That is a silent half-cell of misattributed ownership right at the seam which is precisely where the schedule is trying to put the frozen band.

    The bias by cuts makes the truncation a floor again for one add and one predicated subtract. The non-periodic path keeps the clamp, because there a negative argument really does mean "off the end of the grid".

    pos must be WRAPPED into the domain, exactly as for MFTLGetOwnerProc.

    Parameters:

    • domain The MPI/physical world.
    • k Axis, 0..2.
    • shift Per-axis cut-plane offset.
    • pos A position, already wrapped into the domain.

    Returns:

    The FINE cell index along axis k, clamped to [0, cuts[k]).

    function MFTLRemeshOwnerProc¶

    MFTLGetOwnerProc() evaluated against cut planes offset by shift . 

    static inline int MFTLRemeshOwnerProc (
    const MFTL_Domain * domain,
    const double shift,
    const double pos
)

    Parameters:

    • domain The MPI/physical world.
    • shift Per-axis cut-plane offset from MFTLRemeshPhaseShift().
    • pos A position, already wrapped into the domain.

    Returns:

    The rank owning pos under the shifted decomposition.

    Warning:

    A shifted plane needs a FLOOR, not a truncation. On a periodic axis the argument reaches \(-0.5\), where (int) truncates towards zero and attributes the sliver at the domain minimum to cell 0 instead of to cell cuts-1 across the seam. The wrong rule is still a consistent rule every rank computes the same answer and every structural invariant holds so the only symptom is that the SEAM PLANE NEVER MOVES and the entities on it are frozen in every phase.

    function MFTLRemeshPhaseShift¶

    The per-axis offset of the cut planes for one phase of the schedule. 

    static inline void MFTLRemeshPhaseShift (
    const MFTL_Domain * domain,
    const int group,
    const double phase,
    double out
)

    phase entries are 0 or 1; the eight combinations are MFTL_REMESH_PHASES. An axis with a single cut has no interior plane to move, and shifting it would only rotate the one cell against the periodic seam migration for no gain in coverage so it is left alone.

    Every rank must call this with the same phase before the migration that follows. It contains no MPI, so nothing detects a disagreement, and a disagreement makes ownership AMBIGUOUS rather than merely suboptimal. What keeps it true is that the phase index comes from a compile-time table and a loop counter, never from data.

    Parameters:

    • domain The MPI/physical world.
    • group Per-axis coarsening factors, from MFTLRemeshCoarseningFactors().
    • phase Per-axis phase entry, 0 or 1.
    • out Per-axis cut-plane offset in domain length units.
