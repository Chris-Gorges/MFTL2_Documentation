    Detailed Description¶

    Public Attributes Documentation¶

    variable MFTL_REMESH_PHASES¶

    The eight placements, in units of \(h_k/2\) per axis. 

    const double MFTL_REMESH_PHASES[MFTL_REMESH_NUM_PHASES][3];

    Ordered so that every prefix is as useful as possible: rows 0-1 ((0,0,0), (1,1,1)) make every entity near the planes of ONE axis interior at least once (all but \(O((\delta/h)^2)\) of the mesh); rows 0 and 2-4 form the even-parity set {000, 011, 101, 110}, which covers every entity near the planes of TWO axes; an entity near planes of all three axes needs its unique complementary placement, so all eight rows are required. Placements differing only on an axis with fewer than two (coarse) cells coincide, and the driver de-duplicates them.

    function MFTLRemeshCoarseningFactors¶

    Per-axis coarsening factors that restore \(g_k h_k > 4\delta\) . 

    void MFTLRemeshCoarseningFactors (
    const MFTL_Domain * domain,
    const MFTL_RemeshParameters * params,
    double band,
    int out_group
)

    \(g_k = \lceil 4\delta/h_k \rceil\) on every axis with at least two cells, 1 elsewhere, clamped to cuts[k]. Per axis because the precondition is: a domain thin in x only loses a factor 2, not 8. A coarsened decomposition is only an owner function (MFTL_OwnerMap), so no second communicator exists. The parallel_coarsen cap is applied by the driver, not here.

    Parameters:

    • domain The MPI/physical world.
    • params Supplies max_edge_length and freeze_dilation_rings for the estimate used when band is 0.
    • band The band half-width \(\delta\), e.g. a measured MFTL_RemeshStats::band_bound; 0 falls back to \((\texttt{MFTL\_REMESH\_BAND\_EDGES} + \texttt{rings})\cdot\texttt{max\_edge\_length}\), which overstates the real band about threefold.
    • out_group [3] per-axis factors, each \(\ge 1\).

    ** **

    Performs no MPI. Each rank operates on its own partition. A pure function of replicated data, so all ranks agree without communicating.

    function MFTLRemeshEnsembleParallel¶

    Remeshes a distributed ensemble by shifting the cut planes (SPANNING). 

    int MFTLRemeshEnsembleParallel (
    MFTL_Ensemble * ens,
    const MFTL_RemeshParameters * params,
    MFTL_RemeshStats * stats
)

    Normally reached through MFTLRemeshEnsemble(); public so the schedule can be run at nproc == 1 against the serial answer.

    No ghost position sync is needed inside the loop: every ghost in a rank's pool is frozen on its owner, so the copies are still exact after the sweeps.

    Preconditions: MFTLRegisterMpiTypes() called; the same bodies on every rank in the same order with agreeing next_*_gid (checked in Debug); the same parameter block on every rank with a valid band (checked, see MFTLRemeshEnsemble()); \(h > 4\delta\) (warned about once, see MFTL_RemeshStats::converged).

    Postconditions: the canonical partition (the closing migration IS MFTLRedistribute()); dense global ids, consistent between ghosts and owners; valid topology, current derived arrays and tris.area/normal/center; verts.normal NOT current (use MFTLEnsembleUpdateVertexNormals()); MFTL_FLAG_FROZEN cleared.

    Parameters:

    • ens The ensemble, remeshed in place.
    • params The parameter block.
    • stats May be MFTL_NULL.

    Returns:

    MFTL_SUCCESS, or MFTL_ERROR on every rank if the parameters were refused, or if a migration or the id exchange failed.

    ** **

    Must be called by every rank of the ensemble's communicator.

    function MFTLRemeshMarkFrozen¶

    Flags MFTL_FLAG_FROZEN on every entity this rank may not modify. 

    void MFTLRemeshMarkFrozen (
    MFTL_Object * obj
)

    An owned entity is frozen exactly when another rank holds a copy of it. Redistribution sends a triangle to the owner of each of its corners and edge neighbours, so an owned triangle is replicated iff corner >= verts.n_local || neighbour >= tris.n_local read from tris.verts and tris.neighbors, no distance, no message. Frozen are: every ghost, every replicated owned triangle, and every vertex of a frozen triangle; the flag is cleared elsewhere. Hence an unfrozen vertex has only owned, unreplicated incident triangles, and (with the vertex-complete halo) its whole fan is local. On a ghost-free object nothing is frozen. Stamps the partition dirty, since flags travel with kept ghosts.

    Parameters:

    • obj The mesh.

    Note:

    Requires MFTL_DERIVED_TOPOLOGY (current after a redistribution).

    ** **

    Performs no MPI. Each rank operates on its own partition. It describes this rank's halo; no other rank's answer applies.

    function assign_phase_gids¶

    Turns the phase's locally numbered new entities into globally unique ones, and sums the convergence certificate. 

    static void assign_phase_gids (
    MFTL_Ensemble * ens,
    gid_scratch * g,
    int * extra
)

    The operators know nothing about MPI: two ranks that both split an edge of one body hand out the same id. That is harmless because nothing communicates between the sweeps and this call. Entities created in the phase are those with ids at or above the watermark recorded before the sweeps (g->watermark, {next_vertex_gid, next_triangle_gid} per body); a per-body exclusive prefix sum over the holders gives each rank a disjoint range, and every holder advances its counter by the body's global creation count.

    Parameters:

    • ens The ensemble.
    • g The scratch handle.
    • extra [ MFTL_REMESH_EXTRA_INTS ] convergence counters, summed over all ranks in place by a separate 3-int MPI_Allreduce.

    ** **

    Must be called by every rank of the ensemble's communicator.

    function band_for_frozen_target¶

    The band that would hold the frozen share at or under f_target . 

    static double band_for_frozen_target (
    const MFTL_Domain * dom,
    double delta,
    double f_target
)

    ── One formula, two constants ─────────────────────────────────────────────

    The correctness rule is g[k] = ceil(4*delta / h_k) and the efficiency rule is g[k] = ceil(2*delta / ((1-u) * h_k)), so they differ only by a constant and the second can be expressed as the first applied to an INFLATED BAND. That is why this returns a band rather than a factor: it lets both triggers go through the one published MFTLRemeshCoarseningFactors, which is tested, clamps to cuts[k], and skips uncut axes three behaviours a second implementation would have to reproduce and would eventually stop reproducing.

    ── Where u comes from ─────────────────────────────────────────────────────

    A box loses 2*delta per cut axis, so the unfrozen share is the product over cut axes of (1 - 2*delta/h_k). Requiring each axis to contribute at least u = (1 - f_target)^(1/n_cut) makes the product at least 1 - f_target, and is the only split of the requirement across axes that does not privilege one. Solving 1 - 2*delta/(g*h) >= u for g gives the rule above.

    Check it against the degenerate case: with ONE cut axis, u = 1 - f_target, so the band inflates by 1/(2*f_target) and at a third that is h >= 6*delta which is f = 2*delta/h <= 1/3 read straight off, with no model in between.

    Parameters:

    • dom The MPI/physical world; supplies which axes are cut.
    • delta The measured band half-width.
    • f_target The frozen share the caller is willing to accept, in (0, 1).

    Returns:

    The band to hand MFTLRemeshCoarseningFactors, or delta unchanged when the target is not a constraint.

    ** **

    Performs no MPI. Each rank operates on its own partition. Pure arithmetic on replicated data.

    function check_band_fits¶

    Reports, ONCE per process, that the rank boxes are too small for the shift schedule. 

    static void check_band_fits (
    const MFTL_Domain * dom,
    const MFTL_RemeshParameters * params,
    double band_measured,
    double band_bound
)

    ── Why this warns and does not assert ─────────────────────────────────────

    Because h <= 4*delta makes the scheme DEGRADE, not break. The mesh that comes out is structurally perfect; it simply has bands along the cut planes that no placement ever offered to anyone, so they keep whatever triangles they had. MFTL_RemeshStats.converged says so, and the caller can act on it.

    An assertion would abort a running simulation over a mesh-QUALITY shortfall, which is the wrong trade at 3 a.m. on a cluster. It is also wrong for a duller reason that only showed up under test: freeze_dilation_rings is a documented, supported parameter that WIDENS delta, so a configuration the API invites the caller to try would abort in Debug and run in Release. A knob whose whole purpose is to be conservative must not be the thing that kills the process.

    The one-shot latch is not cosmetic either. A solver remeshes every N timesteps, so a per-call warning is thousands of identical lines and the reliable effect of that is that nobody reads any of them.

    Parameters:

    • dom The MPI/physical world.
    • params Supplies the coarsening cap.
    • band_measured The observed band half-width.
    • band_bound The conservative bound from frozen_band_width().

    Reports on rank 0 when h > 4*delta no longer holds, which is the one precondition whose violation is otherwise completely silent.

    function count_hidden_edges¶

    The convergence certificate: out-of-band edges that THIS placement of the cut planes hides from every rank, split by the operator that would fix them. 

    static void count_hidden_edges (
    const MFTL_Object * obj,
    const MFTL_RemeshParameters * params,
    int * hidden_long,
    int * hidden_short
)

    Needs no fan walk, so a rank's partial view of a neighbour's one-ring cannot give it a wrong answer (unlike counting "approved, then refused by the gate"; see sweep_split in remesh_driver.c). An edge is hidden when its operator's gate refuses it: a split is gated by the two incident TRIANGLES (freeze_blocks_pair), a collapse by the two endpoint VERTICES (freeze_blocks_collapse). The vertex-frozen set strictly contains the triangle-frozen one, so testing long edges with the vertex rule would over-report and suppress the fast exit.

    hidden_long is EXACT. If it is zero and no rank performed an operation, every long edge had both incident triangles unfrozen on the rank counting it, hence owned (every ghost is frozen); the split sweep reached it and MFTLSplitApproved() refuses only DEAD, VISITED or non-canonical edges, both flags being clear at measurement time so it would have been split, contradiction. hidden_short is not exact: a collapse can be refused on merit in both directions (link condition, wing valence, stretch, feature rules), and such an edge stays hidden forever the false alarm the silent-streak exit absorbs. An edge no placement ever offers (the \(h \le 4\delta\) failure) is counted in every phase.

    Called BEFORE the sweeps: in the converged regime, the only one whose value is read, the sweeps change nothing; afterwards, new entities would carry provisional ids that the cross-rank attribution rule cannot compare.

    Parameters:

    • obj The mesh.
    • params Supplies the length band.
    • hidden_long Out-of-band LONG edges hidden by the split gate.
    • hidden_short Out-of-band SHORT edges hidden by the collapse gate.

    function frozen_band_width¶

    Conservative half-width of the frozen band, in length units. 

    static double frozen_band_width (
    const MFTL_RemeshParameters * params
)

    A triangle is replicated when a corner or an edge neighbour is a ghost (one triangle from the plane plus one hop), and a vertex is frozen when any incident triangle is (one more): MFTL_REMESH_BAND_EDGES = 3 edges, each at most max_edge_length (the target would understate it). A dilation ring adds one more.

    Parameters:

    • params Supplies max_edge_length and freeze_dilation_rings.

    Returns:

    \((\texttt{BAND\_EDGES} + \texttt{rings}) \cdot \texttt{max\_edge\_length}\), about three times the measured band.

    function gid_reduce¶

    The per-body exclusive prefix sum, plus the total. 

    static void gid_reduce (
    MFTL_Ensemble * ens,
    gid_scratch * g
)

    ── THE SCOPE IS AUTO, AND IT IS NOT A DETAIL ─────────────────────────────

    MFTL_BODY_REDUCE_SCOPE_AUTO lets MFTLEnsembleExscanBodies() take the route the partition actually permits: the body's HOLDERS over the 26-neighbour graph when every holder set fits inside one neighbourhood, and comm_world when it does not which is exactly what a COARSENED placement makes normal, because a coarse representative is group fine cells away and no local test would call it a neighbour. The same condition MFTLRemeshSyncGhostIds() falls back on, decided by the same one int.

    Pinning this to MFTL_BODY_REDUCE_SCOPE_GLOBAL is a scaling regression THAT NO TEST OF THE MESH CAN SEE. The two routes agree to the bit by construction, so every digest in docs/analysis.md §5.3 reproduces either way; the cost is 3 * n_bodies_global * 2 doubles of staging and two comm_world collectives over a third of that, ONCE PER PHASE, on a rank that may hold a hundred of a million bodies. test_a_droplet_remesh_takes_no_global_reduction (tests/test_body_reduce.c) counts the routes rather than the answer, and is the only thing in the suite that would notice.

    Parameters:

    • ens The ensemble.
    • g The scratch handle; local must be filled in.

    ** **

    Must be called by every rank of the ensemble's communicator.

    function local_band_probe¶

    The band this partition ACTUALLY has, and an upper bound on it. 

    static void local_band_probe (
    const MFTL_Object * obj,
    const MFTL_Domain * dom,
    const double shift,
    double out
)

    ══ WHY THE ESTIMATE IS NOT GOOD ENOUGH, WITH NUMBERS ══════════════════════

    frozen_band_width is 3 * max_edge_length, derived from the reach of the freeze rule: one triangle to the plane, one more to a triangle that reaches it, one more because a vertex is frozen when ANY incident triangle is. It is an upper bound and it is a loose one. Measured on a partitioned sphere in [-1,1]^3 across a sweep of target lengths, the band that actually occurs is

    about ONE edge, not three, and consistently so from target 0.06 to 0.50. The consequence is not academic: h > 4*delta computed from the estimate refuses configurations that work perfectly. At a target of 0.12 on that fixture the estimate says 4*delta = 1.92 against h = 1.0, i.e. "this cannot work", and the pass converges with nothing hidden at every rank count. A precondition that cries wolf by a factor of three is a precondition nobody reads.

    So the band is measured. Two numbers, because they answer different questions:

    out[0] band_measured max over this rank's OWNED FROZEN vertices of the distance to the nearest cut plane. What the band IS, right now.

    out[1] the longest owned edge, which times MFTL_REMESH_BAND_EDGES is a measured upper bound for the band later in the pass. Note it can legitimately exceed params->max_edge_length: a collapse can lengthen an edge past the band, and the split sweep's snapshot bound defers the correction by one iteration.

    ── The trap in out[0], which the obvious spelling walks into ──────────────

    The distance has to be the MINIMUM over axes, then the maximum over vertices. A vertex frozen because of a y plane sits about h/2 from every x plane, so a maximum over axes reports h/2 on the first sample and the measurement is worthless. Axes with cuts < 2 are skipped for the same reason they are skipped in MFTLDomainGetHMin: they have no interior plane to be near.

    LOCAL, no MPI the caller reduces both with one MFTLRemeshAgreeDoubleMax.

    Parameters:

    • obj The mesh.
    • dom The MPI/physical world.
    • shift Per-axis cut-plane offset of the current phase.
    • out {largest frozen distance from a plane, largest owned edge}.

    const MFTL_Object * obj,
    double out
)

    ── Why TRIANGLES and not vertices ─────────────────────────────────────────

    Because the quantity being estimated is the share of a MIGRATION that buys nothing, and the migration's payload is dominated by triangles: a closed mesh has twice as many of them as vertices, and each carries three half-edges. A vertex-based share would be measuring a different, smaller thing and comparing it against a threshold calibrated on this one.

    ── Why it is a running sum and not a fraction ─────────────────────────────

    The ratio has to be taken AFTER the reduction. Averaging per-rank fractions weights a rank holding four triangles the same as one holding forty thousand, and at the partition boundary those are the ranks that differ most which is precisely the population the measurement is about.

    LOCAL, no MPI. The caller reduces both with one MFTLRemeshAgreeDouble (SUM).

    Parameters:

    • obj The mesh, with MFTL_FLAG_FROZEN already current.
    • out {owned triangles, frozen owned triangles}, accumulated into.

    function owns_edge_count¶

    Does this rank count the undirected edge at h , mesh-wide exactly once? 

    static bool owns_edge_count (
    const MFTL_Object * obj,
    int h
)

    The edge is attributed to the owner of the incident triangle of SMALLER GLOBAL ID. Attributing it to "whoever owns a triangle here" instead double-counts every cut edge, once on each side by an amount that GROWS WITH THE RANK COUNT, which is the one shape of error a certificate about partitioning must not have.

    • h Half-edge index.

    true if this rank is the one that should COUNT this undirected edge exactly one rank must, or the certificate double-counts.

    function redensify_global_ids¶

    Makes the ids of both classes a dense permutation of [0, N) again. 

    static int redensify_global_ids (
    MFTL_Ensemble * ens,
    gid_scratch * g
)

    ── The three steps are ordered, and every ordering constraint is silent ───

    • REDUCE first. The prefix sum of the owned counts is what "base + slot" means, and the ghost exchange in step 2 answers with it.
    • EXCHANGE before overwriting. The request is keyed on the OLD id, so the owner must still be holding old ids when it answers. Renumbering first would make every request unanswerable and the reply path treats an unanswerable request as a skip, so the ghosts would quietly keep stale ids instead of failing.
    • OVERWRITE last, by SLOT. Any other rule would need a second table on the owner to answer step 2; numbering by slot makes the answer arithmetic.

    Ghost TRIANGLES are deliberately not exchanged. Redistribution keeps only owned triangles and re-receives every ghost, so a ghost triangle's id is replaced wholesale by the caller's closing migration which is also why that migration has to come AFTER this function and not before it.

    Parameters:

    • ens The ensemble.
    • g The scratch handle.

    Returns:

    MFTL_SUCCESS, or MFTL_ERROR if the ghost id exchange failed.

    function report_fallback¶

    Reports, ONCE per process, that the fallback merged rank boxes. 

    static void report_fallback (
    const MFTL_Domain * dom,
    const MFTL_RemeshStats * st,
    const int group
)

    ── Why this is announced at all ───────────────────────────────────────────

    Because arming the fallback by default converts one silent failure into another. Before, a too-fine partition quietly produced un-remeshed bands. Armed, it quietly produces a run in which 1/(g0*g1*g2) of the ranks do all of the sweeping and the timestep grows by the same factor correct, and mystifying if the first you hear of it is a profile. n_coarse_groups and coarsen_trigger carry the same information for a caller that reads the stats; this is for the one that does not.

    The one-shot latch is the same discipline as check_band_fits, for the same reason: a solver remeshes thousands of times, and the reliable effect of thousands of identical lines is that nobody reads any of them.

    Parameters:

    • dom The MPI/physical world.
    • st Supplies the trigger bitmask and the measured frozen share.
    • group The per-axis factors actually adopted.

    function watermarks_agree¶

    Debug check: every rank agrees on the id watermark of every body.

    The per-phase id blocks are carved out of next_*_gid, so a rank whose watermark differs hands out ids that overlap another rank's block and two entities with one id are merged by the next redistribution's de-duplication into a single, silently wrong entity. Cheaper to find here than there.
